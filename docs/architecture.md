# 아키텍처

`McstClient`는 `culture`, `data_go`, `file_data`에 하나의 `AsyncTokenBucket`을
주입합니다. 개별 클라이언트는 `_http`의 네이티브 HTTPX 비동기 GET을 사용합니다.
`_ratelimit`는 다른 API 라이브러리와 동일한 구현이며 단조 시계와 비동기 잠금을
사용합니다. 토큰 대기 중 취소는 토큰을 소비하지 않습니다.

`_httpx`는 HTTPX가 준비한 다음 리디렉션 요청을 받아 토큰을 획득한 후 송신합니다.
각 재시도도 토큰을 별도로 획득합니다. 자동 auth 재송신은 지원하지 않습니다.
GET의 기본 재시도는 3회이며 429/500/502/503/504와 HTTPX 네트워크 오류에
적용합니다. 401/403과 리디렉션 한도 초과는 재시도하지 않습니다.
백오프는 지수 지연에 최대 10% jitter를 더하고 유한한 Retry-After 값을 반영합니다.

JSON/XML 본문은 HTTP 상태와 별도로 결과 코드를 분류합니다.
`0`, `00`, `0000`, `NORMAL_CODE`, `INFO-000`은 정상으로 처리하고,
`03`/`INFO-200`/NO DATA는 기존 빈 결과 계약을 유지합니다.
인증·쿼터·요청 오류의 타입과 코드 속성은 보존합니다. 분류 후 오류와 디버그
결과의 모든 필드에서 설정 키와 실제 추가 파라미터로 덮어쓴 키를 마스킹합니다.
디버그 결과는 Pydantic 모델, enum, tuple, dataclass 형태를 유지합니다.

파일 상세페이지와 원본 다운로드는 별도 GET입니다. 빈 params를 전달하지 않아
상세페이지 URL의 query를 보존합니다. ZIP 추출, CSV 디코딩/파싱과 파일 쓰기는
`_file_io.run_file_io`로 실행하며, 반복 취소에도 작업 스레드가 끝날 때까지 기다린
다음 취소를 전파합니다. `overwrite=False`는 배타적 파일 생성으로 경쟁을 막습니다.

RustFS는 `_s3`의 SigV4 서명 후 같은 버킷으로 PUT합니다. 서명은 토큰 대기 후
작성하고 PUT의 자동 재시도·리디렉션은 하지 않습니다. 네트워크를 작업 스레드로
감싸지 않습니다. 명시적/환경 변수 자격증명을 사용하며 boto3는 필요 없습니다.

`catalog`의 항목·제공기관·원천 URL은 변경하지 않습니다. 카탈로그와 순수 모델
변환, fixture 저장/replay는 동기 함수입니다. 기본 pytest는 네트워크를 호출하지
않으며, live는 `MCST_RUN_LIVE=1`과 live 마커로 구분합니다.
